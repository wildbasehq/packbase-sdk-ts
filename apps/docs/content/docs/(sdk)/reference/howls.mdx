---
title: pb.howls
description: Fetch, create, delete, like, comment on, rehowl, and report howls.
---

Call `pb.howls(id)` with a howl UUID to get a lazy `HowlHandle`. Creating the handle does not send a request. Await the handle to fetch the howl. Action methods such as `.like()` send only their applicable request.

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
// ---cut---
const howl = await pb.howls('howl-id')
console.log(howl.body, howl.user.username)
```

## Create a howl

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
// ---cut---
const howl = await pb.howls.create({
  tenant_id: 'pack-id',
  body: 'Hello, world!',
  tags: ['art', 'rating_safe'],
})
```

Packbase creates howls in a background job. By default, the SDK starts the job and checks its status. The promise resolves with the completed `Howl`. Application code requires only the `await` above.

`HowlCreateInput` accepts:

| Field | Type | Notes |
| --- | --- | --- |
| `tenant_id` | `string` | Pack UUID. The caller must be a member. |
| `parent_id` | `string?` | Source howl UUID to quote. The quote survives source deletion; use `.comment()` for replies. |
| `content_type` | `'text'?` | The SDK supplies `'text'` when omitted. |
| `body` | `string \| null` | Plain text or HTML. Use `null` only when assets are present. |
| `asset_ids` | `string[]?` | Finalized upload IDs, up to 100. |
| `tags` | `[string, ...string[]]` | Must contain exactly one rating tag, in any position. |

Pass `{ poll: false }` to receive only `{ id }` without a wait. Read [Async Job Polling](/guides/polling) before you use this option. Your application must then monitor the incomplete job.

## Upload assets

`pb.howls.upload` exposes `init`, `append`, `finalize`, and `status`. The SDK injects protocol commands and uses multipart `FormData` for appended blobs.

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
declare const file: Blob
// ---cut---
const initialized = await pb.howls.upload.init({ totalBytes: file.size, assetType: file.type })
if (typeof initialized.asset_id !== 'string') throw new TypeError('Missing upload ID')
const assetId = initialized.asset_id
await pb.howls.upload.append({ assetId, segmentIndex: 0, asset: file })
await pb.howls.upload.finalize(assetId)
await pb.howls.upload.status(assetId)
```

Upload responses are open `JsonObject` values until the server publishes stable response schemas.

Use an image or video MIME type for `assetType`. `append()` uses sequential,
zero-based segment indexes. Finalization checks the declared byte count; IDs are
bound to the current member and expire. A status result currently exposes
`state`, `file_percentage`, `check_after_secs`, and an optional error. An upload
ID is distinct from the future howl/job ID.

## Delete

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
// ---cut---
await pb.howls('howl-id').delete()
```

The signed-in user must have permission to delete a howl. The server does not currently supply a howl edit route.

There is no general body-edit method. Tags and media copyright have separate
editing methods described below.

## Likes

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
const howl = pb.howls('howl-id')
// ---cut---
await howl.like()
await howl.unlike()
```

`like()` sends a bodyless `PUT /howl/:id/like`; `unlike()` sends a bodyless `DELETE /howl/:id/like`. Both are idempotent. A member has at most one like per howl. The author chooses the emoji in user settings; readers use the emoji already stored with the howl.

Every howl includes `likes: { emoji, count, likedByMe }`, even when the count is zero. The default emoji is 🔥. Set `howl_like_emoji` through [`pb.me.settings()`](/reference/me#settings) to choose the emoji for new howls. Changing it leaves existing howls unchanged.

## Comments and rehowls

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
const howl = pb.howls('howl-id')
// ---cut---
const { id: commentId, likes } = await howl.comment('Good post.')
const { id: rehowlId } = await howl.rehowl()
await howl.unrehowl()
```

`comment()` returns `HowlCommentResult`: `{ id, likes }`. Use this returned `likes` summary to reconcile optimistic replies with the server's emoji snapshot; local settings may be stale. Comments are sanitized by the server and limited to 1,024 characters. `unrehowl()` targets the original howl ID.

## Report

```ts twoslash
import { PackbaseSDK, ReportReason } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
// ---cut---
const ticket = await pb.howls('howl-id').report(
  ReportReason.Misinformation,
  'Source material is available here.',
)
```

The returned `ReportResult` contains the moderation ticket's `id` and `status`.

## Public moderation summary

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
// ---cut---
const summary = await pb.howls('howl-id', { context: 'feed' }).moderation()
console.log(summary.status, summary.actions)
```

`moderation()` sends `GET /howl/:id/moderation`. The status is `none`,
`under_review`, or `reviewed`. Public actions are `warning`, `restriction`, and
`content_removed`. The same coarse data can appear as `moderation_summary` on a
howl or comment. Reporter identities, case IDs, private notes, and investigation
details are not included. Normal content visibility still applies.


## Visibility context

`pb.howls(id, { context: 'feed', signal })` retains feed mute filtering during detail hydration, including nested quote and reply previews. A direct read defaults to `context: 'direct'`, preserving muted content intentionally opened through a profile or howl link. Blocking applies in both contexts and returns ordinary `404` responses for inaccessible reads and actions. See [Blocking, muting, and visibility](/reference/visibility).

## Edit media copyright

Only the original howl creator can change its media credit. Regular rehowls resolve to the original howl; quotes retain their own credit.

```ts
await pb.howls(id).setCopyright('© 2024 Artist name')
await pb.howls(id).setCopyright(null) // Restore the creator/year default
```

The credit applies to all media in the howl and is returned as `howl.copyright`. Text is trimmed and limited to 500 characters; blank text also restores the default. The endpoint is `PUT /howl/:id/copyright` with `{ copyright: string | null }`.

## Edit tags

Authors can edit their own howls. Other signed-in members can edit when the author's `allow_tag_edits_from_others` setting is on (the default). This setting applies to existing and future howls. Staff and content moderators retain their moderation permissions; being a pack host alone does not grant a bypass. Replies cannot be edited through this feature. Regular rehowls use the original howl's tags; quote howls retain their own tags.

Fetch current state before editing. `fresh: true` bypasses pending-read sharing and HTTP caches. Use the returned capabilities to decide which controls to show, and send the latest numeric revision with the edit:

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
const id = 'howl-id'
// ---cut---
const howl = await pb.howls(id, { fresh: true })
if (howl.can_edit_tags && howl.tag_revision !== undefined) {
  const updated = await pb.howls(id).setTags({
    tags: ['rating_safe', 'digital_art'],
    explanation: 'Added the medium used in this artwork.',
    expected_revision: howl.tag_revision,
  })
  console.log(updated.tags, updated.tag_revision, updated.edit)
}
```

`setTags()` sends `PUT /howl/:id/tags` and returns `HowlTagEditResult`: `{ tags, moderator_tags, tag_revision, edit }`. Every edit requires a public explanation, including edits to your own howl. Explanations are trimmed and must contain 1–1,000 characters. Send the complete tag list, with at most 100 tags of at most 256 characters each and exactly one rating tag. Members can change the rating when it is not protected. Protected tags must remain unchanged unless the caller can manage tag locks.

Staff and content moderators can pass `moderator_tags` to replace the protected subset alongside the tags. In this endpoint, unlocking a tag leaves it in `tags` when it remains in the supplied tag list. A no-change request does not create an edit. A stale `expected_revision` returns `409` without changing tags or history: fetch fresh state, review the new diff, and submit again with the current revision. Other permission or visibility changes may also reject a save.

The existing `moderatorTags({ tags, explanation, expected_revision })` method sends `PUT /howl/:id/moderator-tags`. It now requires the same explanation and revision and creates public history. Its legacy replacement semantics remove previously protected tags omitted from the new protected set; use `setTags()` to unlock a tag while keeping it on the howl.

## Public tag history

```ts twoslash
import { PackbaseSDK } from '@packbase/sdk-ts'
const pb = new PackbaseSDK()
const id = 'howl-id'
// ---cut---
const page = await pb.howls(id).tagHistory()
for (const edit of page.data) {
  console.log(edit.editor?.username, edit.explanation)
  console.log(edit.added_tags, edit.removed_tags)
  console.log(edit.locked_tags, edit.unlocked_tags)
}
if (page.has_more && page.cursor) {
  const older = await pb.howls(id).tagHistory({ cursor: page.cursor })
}
```

`tagHistory()` sends `GET /howl/:id/tag-history`, reads fresh on every call, and accepts `signal` for cancellation. History is public wherever the howl is visible and is ordered newest first. Each entry contains a string ID, numeric revision, timestamp, editor's public identity (or `null` when unavailable), explanation, and tag and lock diffs. History begins when tracking is deployed; creation does not count as an edit. The history follows the howl's normal access and deletion rules.
